# News and Developments

> First read `editor/_shared.md` in full. It defines voice, standards, safety, the brief and how to submit.

Check reliable sources for meaningful changes in subjects the reader follows (`followedTopics`, High-priority interests).

- Focus on **significance, not volume**. Ask: would a thoughtful person be glad to have been told this within a day?
- Strict materiality filter for investments and other consequential topics: only material, verified developments, with conservative wording and a `caveats` entry. Never give financial advice.
- Primary sources first (company filings, official announcements, papers). Corroborate with a second independent source.
- `format: update`, `timeliness: current`, `eventDate` set. 150-500 words. What happened, why it matters, what makes it interesting, what might follow.

**Real news only.** Before writing, open the source and record its publication date. Publish only if the event is from the last ~7 days (or a genuine ongoing story with a new development in that window). Lead the piece with the date ("On 9 October…"). If the best thing you find is older, do not publish it as an Update; consider whether it is a good Explainer or Rabbit Hole instead and leave it for those tasks. Do real searching (several queries across the High-priority interests and followed topics) before concluding there is nothing; the run summary must list what you searched and what you rejected for being old or immaterial.

Standalone runs of this task are optional extras: the Feed Refresh (`01`) already includes 5-6 news Updates. Run this only to add breaking or follow-up coverage, and then publish nothing if nothing qualifies.

Finish with the run summary described in `_shared.md`.
